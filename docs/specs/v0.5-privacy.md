# Spec v0.5 — Privacy

> Status: implemented (2026-10-04). Follows `v0.4-effects.md`.
> Goal (roadmap): turn off Windows telemetry through the official mechanisms —
> policies, services, scheduled tasks and the firewall — with a dashboard of what is
> blocked.

## 1. What already existed, and what v0.5 adds

`prism allege` (debloat, `sûr` level) already disables the telemetry service
(DiagTrack), the telemetry scheduled tasks (Compatibility Appraiser, CEIP, feedback…),
the advertising ID, activity history and Recall. v0.5 does **not** touch those again:
two journals writing the same values would undo each other on restore. Instead:

| Piece | Where |
|---|---|
| Privacy catalogue: 21 settings (policies and documented Settings options) + 3 firewall rules + 7 read-only checks — 17 entries at the recommended level, 7 more at strict | `config/vie-privee.toml` |
| Plan / apply / restore / dashboard (pure logic, tested without Windows) | `crates/prism-core/src/privacy.rs` |
| Windows: registry, firewall rules, live telemetry connections | `crates/prism-win/src/privacy.rs` |
| CLI `prism vie-privee` and the app's *Vie privée* page | `crates/prism`, `crates/prism-ui` |

## 2. Levels

- **Recommandé (recommended)** — nothing useful is lost: diagnostic logs and full
  memory dumps not sent, no feedback prompts, no tailored experiences, no suggested
  content / app suggestions / tips / recommendations in Settings and Start, sites
  don't read the language list, Start search stays on the PC (no Bing), app launches
  not tracked, typing and handwriting not collected, Edge diagnostic data and
  personalization reporting off; firewall: CompatTelRunner and DeviceCensus cannot
  reach the internet.
- **Strict** — recommended plus settings where something is given up, and each one
  says what (`lose`, shown in the app and validated by the catalogue parser): error
  reports not sent (and `wermgr.exe` blocked), apps cannot read other apps'
  diagnostic info, no input personalization / online speech recognition, Windows
  Copilot off, location off for the whole PC, no cloud clipboard.

## 3. Firewall rules

- Outbound **block** rules of the Windows Firewall, named `Prism OS - <id>`, created
  with `netsh advfirewall firewall` (documented; only the exit code is read, it does not
  depend on the language).
- A rule targets either a **service** (`service=…`, the service SID) or a **program**
  that must be an executable of Windows itself
  (`%SystemRoot%\…\*.exe`). The catalogue parser refuses anything else, and refuses any
  service of the debloat `[[protected]]` list (Windows Update, Defender, licensing,
  time, the services anti-cheats depend on). The same checks run again before each
  write.
- **No rule for the telemetry service (DiagTrack).** The first version had one
  (`service=DiagTrack`). The 40-minute audit showed DiagTrack still connecting with the
  rule in place; the Windows Filtering Platform said why: the allowing filter was
  *Default Outbound* — Prism's block filter existed with a higher weight but its
  service condition never matched DiagTrack's connections. The rule was removed rather
  than left as a false promise; the only effective measure is disabling the service
  (`prism allege`, shown read-only on the dashboard). Program rules were verified
  separately: `curl.exe` gets HTTP 200, fails to connect with a program rule (exit code
  7), and gets 200 again once it is removed.
- The hosts file is never used: Defender flags edits that redirect Microsoft domains.
- Restore deletes only rules Prism created (recorded in the journal); a rule with the
  same name that existed before is kept.

## 4. Registry

- Writable keys (`PRIVACY_REGISTRY_ALLOWLIST` in `privacy.rs`): the official policy
  trees (`HKLM\SOFTWARE\Policies\…`, `HKCU\Software\Policies\…`) and exactly four
  Settings keys (ContentDeliveryManager, Explorer\Advanced, InputPersonalization,
  International\User Profile) — not their subkeys. Checked in the catalogue and again
  before writing.
- Journal `%ProgramData%\Prism\vie-privee.json`: original value of each setting (or its
  absence) and the rules created, saved after each change; re-applying never overwrites
  an original. `prism vie-privee restore` puts everything back.

## 5. Dashboard

- One row per protection: in place / not applied / component absent from this PC /
  unknown (with the error). Absent components do not count in the score.
- Read-only rows show what `prism allege` already does (telemetry service and tasks,
  minimum telemetry policy, advertising ID, activity history, Recall), labelled with
  the module in charge.
- **Telemetry right now**: TCP connections currently open by the monitored components —
  the telemetry service's process (`QueryServiceStatusEx`) and the blocked programs —
  read with `GetExtendedTcpTable` (what `netstat -o` shows), refreshed every 3 s in the
  app.

## 7. Not done

- Per-connection blocked counter: the Windows Firewall log does not say which rule or
  program dropped a packet; the security audit can, but enabling it is a system-wide
  audit-policy change, used only for the measurement.
- Microsoft Store apps' own telemetry and third-party apps (Steam, Discord, NVIDIA…):
  outside Windows' official policies; candidates for opt-in firewall rules later.
- Edition limits: on Home/Pro, Windows raises `AllowTelemetry = 0` to "required"
  (documented by Microsoft); the firewall rules apply on every edition.
