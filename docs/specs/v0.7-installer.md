# Spec v0.7 — Installer

> Status: installer implemented (2026-10-04). Signed updates and FPS measurements on real
> hardware still to do. Follows `v0.6-customization.md`.

## 1. MSI built from Linux

- `installer/prism.wxs`, compiled with **wixl** (msitools) — no Windows needed to
  package. CI job *Installateur MSI*: takes the binaries built on the real Windows runner
  (artifact `prism-windows-x64`), builds `prism-<version>-x64.msi` (artifact
  `prism-installer`) and checks the package: the three programs are present and the
  clean-up action sits between `InstallInitialize` and `InstallFinalize`.
- Per-machine install in `Program Files\Prism`, Start menu shortcut to the app, entry
  in *Installed apps*, in-place upgrades (fixed UpgradeCode, `MajorUpgrade`), licences.
- `wixl` limits met and worked around: no `Environment` element (PATH is handled by
  Prism itself, below); `Before="RemoveFiles"` was sequenced before `InstallInitialize`
  (error 2762 on uninstall, found in the VM) — the action is anchored after
  `InstallInitialize`.

## 2. Install and uninstall actions

- **After install** (`prism apres-installation`, system account): adds the install
  folder to the system `PATH`, written back as `REG_EXPAND_SZ` — its original type;
  plain text would stop `%SystemRoot%` entries from expanding — and broadcasts
  `WM_SETTINGCHANGE`. PATH edits are pure, tested logic (`paths::path_with` /
  `path_without`: case and trailing backslash ignored, other entries untouched).
- **Before uninstall** (`prism desinstaller [LogonUser]`, system account, only on a
  real removal — not during an upgrade):
  - the user's part must run in the user's session: that is where the Prism Bar, the
    appearance settings (SystemParametersInfo) and the user's `HKCU` live. Running it
    as SYSTEM would write SYSTEM's profile. Prism therefore re-runs itself in the
    user's session with administrator rights (one-off scheduled task, interactive,
    highest privileges), waits for it to finish (2 minutes at most) and deletes the
    task;
  - in the session: stops `prism watch` and applies its journals (as its own restart
    would), stops the Prism Bar (restores the Windows taskbar, per-app transparency and
    tiled windows), restores privacy, debloat, appearance and startup apps, deletes the
    autostart tasks;
  - then, as SYSTEM: removes the PATH entry and the scheduled tasks.
- **Windows taskbar state**: the state before Prism hid it is now saved on disk
  (`barre-windows.txt`) and never overwritten while it exists — a bar killed by force
  used to make the next one record "hidden" as the original state.

## 3. Verified in the Windows 11 VM

| Check | Result |
|---|---|
| `msiexec /i` | code 0; files in `Program Files\Prism`; PATH updated, still `ExpandString`; Start menu shortcut; *Prism OS 0.1.0* in Installed apps |
| Upgrade 0.1.0 → 0.1.1 | one entry left, files replaced |
| `msiexec /x` with privacy applied (17 protections, 3 firewall rules) and the bar running | code 0; folder removed; PATH entry removed (type kept); bar stopped; 0 Prism firewall rules; privacy journal empty; HKCU values removed in the user's hive; temporary task deleted |
| Bar hides the taskbar, is killed by force, restarted, then Prism is uninstalled | original state kept (`0`) across the kill; taskbar visible again after uninstall |

## 4. Not done yet

- **Code signing**: the MSI and the programs are not signed — Windows SmartScreen will
  warn on first run. Signing needs a code-signing certificate owned by the project.
- **Updates**: no update channel yet (planned with signing: a signed release feed,
  verified before installing).
- FPS measurements on real gaming hardware.
