# Spec v0.4 — Effects engine (design)

> Status: design, before implementation (2026-10-04).
> Request from the product owner: effects beyond Windows' own animations, as on
> Bazzite/KDE — modern deformations, jelly ("wobbly") windows, a genie/suction effect on
> minimize — and transparency configurable element by element.

## 1. Constraint

On Linux, the compositor (KWin) is open and loads effect plugins. On Windows, the
Desktop Window Manager is closed and exposes no extension point for custom window
effects. Prism will **not** modify system components to get one: that is precisely what
anti-cheats watch for (rules 1, 3 and 5 of `anticheat-rules.md`).

## 2. Approach: effects rendered by Prism, with official APIs

Prism renders the effect itself, in its own transparent, click-through overlay window,
during the short moment of a window transition:

1. **Detect the transition** with official accessibility events received in Prism's own
   process (`SetWinEventHook`, out-of-context): minimize start/end, window shown/hidden,
   move/size start/end.
2. **Get the window's image** with Windows.Graphics.Capture, the public screen-capture API
   used by OBS and the Snipping Tool (or the last frame captured just before the event).
3. **Animate a deformed copy** in the overlay on the GPU: a textured mesh whose vertices
   follow the effect's curve (genie: funnel towards the window's Prism Bar button; jelly:
   spring-damped vertices; zoom, fold, burn-in/out, fade…).
4. **Hand back to Windows**: the real window finishes its own state change underneath;
   Windows' built-in minimize animation is switched off through the Appearance settings
   so the two do not overlap.

## 3. Effects (first set)

| Effect | Trigger | Notes |
|---|---|---|
| Genie / suction | minimize, restore | towards / from the Prism Bar button |
| Jelly open/close | window shown / closed | spring physics, configurable stiffness |
| Zoom + fade | open, close | duration and curve configurable |
| Glide | maximize, snap | eased position/size interpolation |
| Jelly while dragging | move | prototype only: latency must stay invisible, otherwise dropped |

Every effect: on/off, duration, curve (ease-out, spring, bounce), intensity.

## 4. Safety rules

- Never on a game (Game Mode classification + detected library folders), never on a
  fullscreen window, never when Game Mode is active.
- Never on protected processes (anti-cheats, security, system).
- Capture is in-memory only, frame by frame, never written to disk.
- The overlay is click-through and never takes focus.
- Effects are skipped (not queued) if the GPU is busy or a frame budget is missed.

## 5. Open questions to settle with measurements

- Latency from event to first effect frame (target: under one frame at 60 Hz).
- GPU/CPU cost of the overlay on an integrated GPU.
- Behaviour with the capture border shown by some Windows versions.
