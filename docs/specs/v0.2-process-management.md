# Spec v0.2 — Permanent process management, startup, game settings

> Status: implemented and tested (2026-10-04). Follows `v0.1-game-mode.md`.

## Goal (Florian)

"Je veux que l'OS soit plus léger et performant que Windows **en général**, pas que
pour le gaming, mais avec un accent plus poussé lors des sessions de gaming."
(I want the OS to be lighter and faster than Windows **in general**, not just for
gaming, but with a stronger emphasis during gaming sessions.)

Hence two levels running at the same time in `prism watch`:

| | Daily Mode | Game Mode |
|---|---|---|
| When | always, with or without a game | as soon as a game is running |
| Who | **idle** background apps | the whole background |
| CPU priority | unchanged | `BelowNormal` |
| EcoQoS, low memory priority | after `daily_eco_after_minutes` of inactivity | immediately |
| Efficient cores / die without 3D cache | after the same delay | immediately |
| RAM returned | after `daily_trim_after_minutes` | when the game starts |
| RAM monitoring (priority-0 purge) | below `daily_purge_below_percent` | below `purge_when_free_below_percent` |
| Noisy services paused | no | `pause_services` (WSearch) |
| Frozen apps | no | `suspend_in_game` (empty list by default) |
| Undo | as soon as the app comes back (foreground or activity) | at the end of the session |

## 1. Daily Mode (`crates/prism-core/src/daily.rs`)

- **Idle** = less than 1% of one core since the previous pass **and** not in the
  foreground (`GetForegroundWindow`).
- An app that becomes active again, or that the user brings back to the foreground, is
  **restored immediately**: we never slow down what is being used.
- During a game, Daily Mode no longer eases new apps (Game Mode does it harder), but it
  still restores any app the user brings back to the foreground.
- Its own journal, `%ProgramData%\Prism\quotidien.json`, read back at startup (recovery
  after a hard shutdown verified in the VM: 22 settings restored).

| Profile | EcoQoS after | RAM returned after | Purge below |
|---|---|---|---|
| Gaming | 5 min | 30 min | 15% free |
| Balanced | 10 min | 60 min | 10% |
| Cyber | 15 min | 90 min | 10% |

**Pitfall found in the VM**: the kernel time spent trimming is charged to the trimmed
process. On the next pass, the app looked active and was wrongly "restored". The
measurement that follows a trim is therefore ignored (test
`an_idle_app_is_eased_after_5_minutes…`).

## 2. Cores (`crates/prism-core/src/cores.rs`)

The game is never touched (anti-cheat rule no. 1): the **background** is relegated
instead, which leaves the best cores free for the game.

| Processor | Detection | Background on |
|---|---|---|
| Intel hybrid (12th gen+) | different efficiency classes (`GetSystemCpuSetInformation`) | E-cores |
| Dual-die Ryzen X3D (7950X3D, 9950X3D) | different L3 sizes (`GetLogicalProcessorInformationEx`) | die without 3D cache |
| Homogeneous, < 8 logical cores, VM | — | nothing |

A process whose cores have already been chosen (by the user or another tool) is not
modified. Mechanism: `SetProcessDefaultCpuSets` (a preference, not a hard affinity:
Windows can spill over if the chosen cores are saturated).

## 3. Startup applications (`demarrage.rs`, `config/demarrage.toml`)

- Sources: user `Run`, machine `Run`, 32-bit machine `Run`, Startup folders.
- Disabling = `StartupApproved` value (leading byte 03 + timestamp), **exactly** what
  Task Manager's "Désactiver" ("Disable") button does. The app is neither removed nor
  modified.
- Advice: `desactiver` (disable; applied by `prism demarrage recommande`), `optionnel`
  (optional; explained, never applied without a request), `garder` (keep).
- Protected, even on explicit request: Windows Security and anti-cheats (Vanguard,
  EAC, BattlEye, FACEIT).
- Not covered: startup tasks of Store apps (MSIX). To do.

## 4. Game settings (`jeu` level of `prism allege`)

Windows Game Mode, hardware-accelerated GPU scheduling (HAGS), optimizations for
windowed games, mouse acceleration turned off. The registry written by Prism is limited
to an **allowlist** of keys (`REGISTRY_ALLOWLIST`), checked twice: when the catalog is
loaded and right before writing.

## 5. Added safety rules

- **Session 0 is never touched.** Found in the VM: launched over SSH, Prism saw
  `wmiprvse.exe` (WMI, queried by anti-cheats) and `sppsvc.exe` (licensing) as
  background processes. They are now protected in all circumstances, and `prism status`
  warns if Prism is running outside the user's session.
- A paused service is only restarted if Prism stopped it itself.
- A protected service cannot appear in `pause_services` (configuration rejected).
- The freeze list is empty by default: a frozen program stops responding entirely.
