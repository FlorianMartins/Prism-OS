# Spec v0.3 — Interface and customisation

> Status: implemented (2026-10-04). Follows `v0.2-process-management.md`.
> Goal (from the product owner): a Windows that is as customisable as a Linux desktop
> (Bazzite, Arch) — taskbar size and position on any edge, window animations,
> transparency, system widgets — without losing anti-cheat compatibility.

## 1. What can and cannot be done on a genuine Windows

| Wish | How Prism does it | Possible? |
|---|---|---|
| Taskbar on any edge, any size | Prism Bar: our own window docked with the official app-bar API (`SHAppBarMessage`) | Yes |
| Hide the Windows taskbar | Windows' own "auto-hide" setting (`ABM_SETSTATE`), restored on exit | Yes |
| Minimize/maximize, open/close, menu and tooltip animations, smooth scrolling | `SystemParametersInfo` (the settings of Windows' "Performance Options" dialog) | Yes, on/off |
| Transparency, shadows, dark/light theme, accent on title bars | `SystemParametersInfo` and documented personalisation registry values | Yes |
| Per-app window transparency | Layered-window alpha on that app's windows | Yes (not for games) |
| System widgets on the desktop (Conky-like) | Our own windows, kept at the bottom of the Z-order | Yes |
| Hyprland-style animations (custom curves, bouncing, window move animations) | Would require injecting code into the Desktop Window Manager | **No, by design** |
| Tiling window manager | Possible with `SetWindowPos` on other windows | Planned |

Injection into DWM or Explorer is exactly what anti-cheats watch for (anti-cheat rule
1 and 3). Prism's own windows (app, bar, widgets) can be animated freely.

## 2. `prism-ui` — the app

- egui on wgpu (DirectX 12; WARP software rendering when there is no GPU, e.g. in a VM).
  ~11 MB binary, ~58 MB RAM: it is meant to be closed while playing.
- Talks only to the `Backend` trait: the Windows backend calls the same functions and
  journals as `prism.exe`, so anything done in the app can be undone from the command
  line and vice versa. A mock backend renders realistic data for tests.
- Pages: Dashboard, Games (+ console mode), Startup, Debloat, Appearance, Cyber tools.
- Limited mode when not elevated, with "Relancer en administrateur" (relaunch as
  administrator, UAC).
- Tested by rendering every page off-screen (`egui_kittest`) and checking the images:
  non-empty theme, and **no content overflowing the right edge** (a real regression
  found on a screenshot, now a test).
- Lessons from the screenshots: egui's bundled font lacks some symbols (◆ ⏻ ● ←),
  so icons are limited to glyphs verified on a rendered glyph sheet; a two-column grid
  inside half the width overflowed; the spacing between two allocated columns must be
  subtracted from the second one.

## 3. Appearance (`prism-core/src/apparence.rs`, `config/apparence.toml`)

- 20 settings in four groups (Animations, Effects, Theme, Responsiveness), each with its
  options, explanation and Windows mechanism.
- Presets: **Performance max** (everything instant), **Fluide** (all animations, faster
  submenus), **Réglages d'origine** (restore the journal).
- Registry writes limited to 4 personalisation keys (`APPEARANCE_ALLOWLIST`); a
  `WM_SETTINGCHANGE` broadcast makes Explorer apply theme changes without a restart.
- The catalogue is parsed strictly. A test found that serde's untagged enums silently
  ignored unknown keys inside a setting: each variant is now its own strict struct.
- Journal `%ProgramData%\Prism\apparence.json`: switching presets never overwrites the
  original value; restore puts back exactly the factory state, including deleting values
  that did not exist.

## 4. Prism Bar (`prism-bar.exe`, `prism-win/src/bar_app.rs`)

- **Native Win32/GDI**, ~455 KB, a few MB of RAM: it runs all the time, so it must not
  carry a GPU UI stack.
- Docked with `ABM_NEW` / `ABM_QUERYPOS` / `ABM_SETPOS` on the chosen edge; the shell
  then keeps other windows out of its band. DPI-aware (per-monitor v2).
- Options: edge, thickness 24–96 px, margin 0–32 px (floating bar), opacity 40–100 %,
  rounded corners (DWM corner preference), hide the Windows taskbar, hide in fullscreen.
- Widgets: Start (sends the Windows key), open windows (enumerated like a taskbar,
  cloaked and tool windows excluded, click to activate), CPU (`GetSystemTimes`), RAM,
  GPU (PDH counters; "—" when unavailable), network (`GetIfTable2`, hardware interfaces
  only), Game Mode (from `etat.json`), clock.
- Hides itself when Windows notifies a fullscreen app (`ABN_FULLSCREENAPP`).
- Layout is pure logic in `prism-core/src/bar.rs` (4 edges, floating, clamping, never
  overflowing with many windows), unit-tested on Linux and reused by the app's live
  preview, so the preview and the real bar cannot disagree.
- Settings in `%ProgramData%\Prism\bar.json`, re-read every second: changes in the app
  apply live. Old files without the newer fields still load.

## 5. Desktop widgets

- Clock (French date), system panel (CPU, RAM, GPU, network), CPU/RAM/GPU graphs,
  network speed. Same process and renderer as the bar.
- Dragged anywhere with the mouse (`WM_NCHITTEST` → caption); position saved on release.
- Forced to the bottom of the Z-order (`WM_WINDOWPOSCHANGING`), shared opacity setting,
  hidden together with the bar in fullscreen.

## 6. Per-app transparency

- Rules `process pattern → opacity` (floor 30 %), applied by the bar to matching
  top-level windows.
- Never applied to: a game (same rules as Game Mode, including detected library
  folders), a fullscreen window, or a window that already manages its own transparency
  (`WS_EX_LAYERED` already set).
- The original extended style is remembered per window and restored when a rule is
  removed or the bar stops.

## 7. Scheduled-task debloat (in `prism allege`)

- 12 telemetry tasks (Compatibility Appraiser / CompatTelRunner, CEIP, SQM, disk
  diagnostics, feedback, maps, error reporting…) through `schtasks.exe`.
- State read from the task XML, which is not localised (the text output says
  "Désactivé" on a French Windows), and only inside `<Settings>`: triggers have their
  own `<Enabled>` element.
- Protected task folders (Windows Update, Update Orchestrator, Defender, TPM, time sync,
  BitLocker, Store, Xbox) are refused in the catalogue and at execution time.

## 8. Not done yet

- Prism as a Windows service (today: scheduled task at logon, which keeps it in the user
  session — required by the session-0 rule).
- Tiling window manager (komorebi-like).
- Multi-monitor Prism Bar (primary monitor only for now).
- Real-hardware validation of the bar and widgets (verified in code and CI; the VM run is
  pending).
